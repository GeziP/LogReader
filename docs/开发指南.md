## 开发环境设置

### 系统要求

- **操作系统**：Windows 10+、macOS 10.14+、Linux (Ubuntu 18.04+)
- **Qt 版本**：5.12 或更高版本（推荐 5.14.2）
- **编译器**：GCC 7+、Clang 6+、MSVC 2017+
- **磁盘空间**：至少 10GB 可用空间

### 必需工具

- **Qt 框架**：UI 开发
- **CMake**：构建系统
- **LLVM/Clang**：代码格式化和静态分析
- **Cppcheck**：静态分析
- **Python**：脚本和预提交钩子
- **vcpkg**：C++ 包管理器

## 工具安装

### Windows（D 盘安装）

我们推荐在 D 盘安装开发工具，以便更好地管理磁盘空间。

```powershell
# 以管理员身份运行 PowerShell
cd <项目根目录>
.\scripts\setup_windows_d_ascii.ps1
```

此脚本将安装：
- LLVM/Clang（包含 clang-format 和 clang-tidy）
- Cppcheck
- Python 和 pre-commit
- vcpkg 和 Microsoft GSL

### Linux

```bash
# 安装依赖
sudo apt update
sudo apt install cmake build-essential clang clang-format clang-tidy cppcheck python3 python3-pip git

# 安装 pre-commit
pip3 install pre-commit

# 设置 pre-commit 钩子
cd <项目根目录>
pre-commit install
```

### macOS

```bash
# 使用 Homebrew 安装依赖
brew update
brew install cmake llvm cppcheck python git

# 将 LLVM 添加到 PATH
echo 'export PATH="/usr/local/opt/llvm/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc

# 安装 pre-commit
pip3 install pre-commit

# 设置 pre-commit 钩子
cd <项目根目录>
pre-commit install
```

## 开发工作流程

### 1. 创建 Issue

首先创建一个描述功能或 bug 的 Issue。

### 2. 创建分支

从主分支创建一个功能分支：

```bash
git checkout main
git pull
git checkout -b feature/your-feature-name
```

### 3. 本地开发

在你的分支上开发功能或修复 bug。

### 4. 本地验证

在提交之前，运行本地 CI 测试脚本来验证你的更改：

```bash
# Windows
.\scripts\local_ci_test_ascii.bat

# Linux/macOS
./scripts/run_cppcheck.sh
```

此脚本检查：
- 代码格式（clang-format）
- 翻译文件
- CMake 配置
- 静态分析（cppcheck）
- 文件结构

### 5. 预提交检查

提交时，预提交钩子将自动运行以检查：
- 代码格式
- 静态分析
- CMake 文件正确性
- 基本检查（行尾空格、文件结尾等）

### 6. 拉取请求

创建一个到主分支或开发分支的拉取请求。GitHub Actions 将自动运行 CI/CD 工作流程。

## CI/CD 流水线

### 质量 CI 工作流

`quality.yml` 工作流在每个拉取请求和推送到主/开发分支时运行：

- **静态分析**：在 Ubuntu、Windows 和 macOS 上运行
  - clang-format 检查
  - clang-tidy 分析
  - cppcheck 分析

- **Sanitizers**：在 Ubuntu 和 macOS 上运行
  - 地址和未定义行为 sanitizers

- **覆盖率**：在 Ubuntu 上运行
  - 代码覆盖率分析
  - 将结果上传到 Codecov

### 发布工作流

`release.yml` 工作流在推送标签或手动触发时运行：

- **构建 Windows**：创建 Windows 可执行文件并打包
- **构建 Linux**：创建 Linux 可执行文件并打包
- **构建 macOS**：创建 macOS 应用程序包并打包
- **创建发布**：创建包含所有构建产物的 GitHub 发布

## 代码质量标准

### 编码风格

- 遵循项目的 `.clang-format` 配置
- 适当使用 C++17 特性
- 对于 Qt 相关代码，遵循 Qt 编码约定

### 文档

- 为所有公共 API 函数和类编写文档
- 为复杂算法或逻辑添加注释
- 保持文档与代码更改同步

### 测试

- 为新功能编写单元测试
- 确保现有测试通过你的更改
- 争取高代码覆盖率

## 问题排查

### 常见问题

#### CMake 配置失败

- 检查 Qt 是否正确安装并在 PATH 中
- 验证 CMAKE_PREFIX_PATH 包含 Qt 目录
- 对于 Windows，尝试：`-DCMAKE_PREFIX_PATH="E:\software\QT\5.14.2\mingw73_32"`

#### 预提交钩子失败

- 更新 pre-commit：`pre-commit autoupdate`
- 检查 GitHub 仓库的网络连接
- 必要时使用 `--no-verify` 运行，但在 PR 前修复问题

#### 构建错误

- 检查编译器与 Qt 版本的兼容性
- 验证所有依赖项都已安装
- 清理构建目录并重新构建
