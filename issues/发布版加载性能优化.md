# 发布版加载性能优化

## 背景
- 现象：本地工程（Qt5.14.2）运行流畅，但通过 CI 发布的 Windows 便携包（Qt 6.5.3）加载同样的日志文件明显更慢。
- 日志文件编码：UTF-8，本地磁盘。

## 影响范围
- 文件加载阶段（读取/解析/模型插入/界面刷新）。

## 变更概览（已提交）
1. Qt6 分支尊重用户选择编码
   - 文件：`src/core/logloader.cpp`、`src/ui/logviewer.cpp`
   - 变更：`QTextStream` 在 Qt6 下使用 `QStringConverter::encodingForName(...)`；编码非法时给出错误提示。
2. 进度计算更精确
   - 文件：`src/core/logloader.cpp`
   - 变更：`processedBytes = file.pos()` 替代基于行长度的估算。
3. 降低 UI 刷新频率
   - 文件：`src/ui/logviewer.cpp`
   - 变更：
     - 将 `LogLoader` 分块大小从 5000 提升到 20000。
     - 加载期间 `logTreeView->setUpdatesEnabled(false)`，结束后恢复；同时设置/恢复等待光标。

## 预期收益
- 减少 UI 重绘次数，降低大规模模型插入引发的布局/绘制开销。
- Qt6 下编码处理与本地一致，避免潜在的转换开销或异常路径。
- 进度条更平滑、精确。

## 排期与验证
- 本地自动化打包脚本：`scripts/local_build_test.bat`（如环境缺少 qmake 或 windeployqt，请先配置 Qt 工具链到 PATH）。
- 验证建议：
  1) 使用同一日志文件（UTF-8，>100MB）对比：修改前/修改后 Release 包加载耗时；
  2) Windows Defender 排除打包目录进行对照（可显著降低 I/O 干扰）；
  3) 观察进度条推进是否连续、卡顿是否缓解。

## 后续可选优化（按需）
- 在后台线程累积所有数据，完成后一次性 `beginResetModel` 赋值（进一步减少刷新）。
- 使用 `QElapsedTimer` 打点阶段耗时（I/O、正则、时间解析、模型插入）。
- 如果瓶颈在正则与时间解析：改用手写解析（`QStringView` 子串解析）替换 `QRegularExpression`/`QDateTime::fromString`。

## 风险评估
- 变更均为兼容性优化，功能和 UI 行为不变；已添加非法编码的显式报错。
