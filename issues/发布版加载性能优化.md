# 发布版加载性能优化任务

## 问题描述
- **现象**：本地Qt Creator运行程序加载文件约5秒，发布版本加载同样文件约50秒
- **影响**：性能下降10倍，严重影响用户体验
- **环境差异**：本地Qt 5.14 MinGW vs CI Qt 6.5.3 MSVC2019

## 根本原因分析
1. **主要原因**：LogLoader中每行都调用file.pos()，对大文件产生百万次系统调用
2. **次要原因**：31处qDebug()调试输出在发布版本中未完全禁用
3. **环境原因**：MSVC环境下file.pos()性能比MinGW差，编译参数过度激进

## 解决方案
### 阶段1：核心性能优化
- [x] 优化LogLoader文件位置追踪，移除file.pos()调用
  - 改用字符串长度累加方式计算进度
  - 避免每行都调用系统调用file.pos()
- [x] 彻底禁用所有qDebug调试输出
  - 使用LOG_DEBUG_ENABLED条件编译宏包装所有31处qDebug调用
  - 确保Release版本完全移除调试输出

### 阶段2：编译配置优化  
- [x] 优化release.yml中的激进编译参数
  - 移除/GL（全程序优化）、/Ob3（激进内联）、/fp:fast等可能有害的选项
  - 保留基本的/O2优化和安全的优化选项
- [x] 强化CMakeLists.txt中的调试禁用机制
  - 为所有平台添加调试输出禁用
  - 添加QT_NO_INFO_OUTPUT等更强的禁用选项

### 阶段3：代码层面优化
- [ ] 优化正则表达式性能
- [ ] 优化信号发射频率

## 预期效果
- **主要目标**：文件加载速度提升5-10倍，从50秒降低到5-10秒
- **次要收益**：应用启动更快，界面响应更流畅
- **稳定性提升**：避免过度优化导致的不稳定问题
- **验证方式**：通过CI构建测试实际性能改善

## 技术总结
1. **根本问题**：file.pos()系统调用过度频繁是主要瓶颈
2. **次要问题**：qDebug调试输出在Release版本中未完全移除  
3. **初次优化问题**：字符串长度计算方法错误（Unicode字符数≠字节数）
4. **chunkSize问题**：从默认5000增加到20000可能导致UI卡顿
5. **修正策略**：保守优化，每100行调用一次file.pos()，chunkSize改回5000
6. **验证要点**：确认文件加载时间显著改善且功能正常
